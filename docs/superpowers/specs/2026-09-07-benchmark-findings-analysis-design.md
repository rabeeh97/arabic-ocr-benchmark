# Benchmark findings & analysis layer (error anatomy, difficulty, model landscape, ops)

Date: 2026-09-07
Status: approved design, pre-implementation
Path class: architectural

## Problem

The benchmark now has ~9k scored lines across ~15 models and 6+ datasets, but
everything downstream of the raw numbers stops at per-`(model, dataset)`
aggregates: `summary.csv`, the leaderboard matrix, a cost table, and a
best/worst line browser. There is no systematic view of *what* the models get
wrong — which Arabic letters they confuse, whether errors are misreadings or
hallucinations, which samples are hard for everyone (vs. mislabelled), how
models cluster, what the accuracy ceiling of an ensemble would be, or how much
of the "error" column is actually rate-limiting and refusals.

We want a dedicated analysis layer that turns the stored results into insight:
a computed `findings.json`, a new **Findings & analysis** tab in the published
leaderboard with hand-rolled visualisations, and a companion notebook with the
richer matplotlib treatment.

## Scope (decided with the user)

- **New pure-Python package** `src/arabic_ocr_bench/analysis/`. A single-pass
  alignment engine builds one compact `AlignmentRecord` per prediction; every
  finding is a pure reduction over `list[AlignmentRecord]` + the existing
  `scores.jsonl`. (Approach A of three considered; B = independent re-readers,
  C = pandas-in-notebook — both rejected.)
- **New CLI** `bench analyze <results-dir> -o results/findings.json`.
  `make_leaderboard.py` imports the same code and builds the document in-memory
  when `findings.json` is missing or older than the newest run, then writes it —
  so `bench run --report` and the notebooks get it for free.
- **`results/findings.json`** committed alongside `results/leaderboard.{html,json}`.
- **Leaderboard gains a real top-level tab**: `Leaderboard` | `Findings &
  analysis`. Existing sections are unchanged and move under the first tab.
- **Charts in the leaderboard are hand-rolled SVG + CSS + vanilla JS** — zero
  external dependencies, consistent with the current bespoke style, no CSP
  concerns, renders offline.
- **New notebook** `notebooks/09_findings.ipynb`, generated by
  `build_notebooks.py`, committed with empty outputs, runnable in Colab or
  locally. matplotlib primary; seaborn optional (`pip install`, every plot has a
  matplotlib-only fallback). Uses the *same* `analysis` code path as the
  leaderboard — no divergent logic.
- **`numpy`** promoted to an explicit core dependency (already transitively
  present via pandas). Bootstrap CIs and the Bradley–Terry fit are pure numpy.
  **No scipy.**

Out of scope (deferred to a follow-up):

- **#18 image-property correlations** (resolution / contrast / ink density /
  skew vs. CER) — needs an image-feature extraction pass over the datasets.
- **#19 script-style / era breakdown** — needs dataset-level style tags that do
  not exist yet.
- Re-deriving contamination: `training/contamination.py` stays the source; the
  findings layer only *cross-references* its output when present.
- Interactive plotly in the notebook — optional, not required by any finding.

## Architecture

### Package layout

`src/arabic_ocr_bench/analysis/`

| module | responsibility |
| --- | --- |
| `loader.py` | collect + dedupe predictions/scores across `results/*/` (the merge logic currently inline in `make_leaderboard.py._merge_runs` is lifted into a shared helper both call), yielding `PredRow(model, dataset, sample_id, gt, pred, score_row, error, attempts, latency_ms, cost_usd, tokens)` |
| `align.py` | `AlignmentRecord` dataclass + `build_record()`; the rasm table and Arabic letter-group tables |
| `charstats.py` | confusion matrix, per-letter / per-group error rate, S/I/D split, rasm-vs-full gap, digit-script swaps, presentation-form leakage, frequent rewrites, spacing share, length bias (findings sections 1 & 2) |
| `diacritics.py` | per-mark missed/inserted/substituted, diac-F1-vs-CER, density context (section 3) |
| `difficulty.py` | consensus-hard / consensus-easy / discriminative / suspected-bad-GT samples, CER-vs-length curve, per-`(model,dataset)` CER distribution quantiles, CER ECDF (section 4) |
| `modelcmp.py` | agreement matrix + clustering order, oracle / ROVER ensemble ceiling, bootstrap CIs on CER and on rank, pairwise win-rate + Bradley–Terry, metric-correlation matrix, normalization-profile decomposition (section 5) |
| `operational.py` | cost–accuracy Pareto, latency quantiles, failure-cause decomposition, retry / rate-limit stats, empty-output rate, coverage grid (section 6) |
| `refusal.py` | ordered heuristic ruleset producing `failure_class` |
| `corpus.py` | GT charset coverage, char-frequency (Zipf), diacritization density, line-length stats, leaderboard churn across metrics, contamination cross-reference (section 7) |
| `findings.py` | orchestrator: `build(results_dir, *, seed=1234) -> dict`; caps per-section row counts; guarantees JSON-serialisable output (no numpy scalars) |

### CLI

`bench analyze <results-dir> [-o results/findings.json] [--dump-records PATH]`
added to `src/arabic_ocr_bench/cli.py`. `--dump-records` writes the full
`AlignmentRecord` list to parquet for notebook-side ad-hoc slicing (not part of
the normal flow).

`make_leaderboard.py`: after `collect()`, call
`analysis.findings.build(target)` when `results/findings.json` is absent or its
mtime predates the newest run dir; write it; pass the dict into the renderer.

### `findings.json` schema

One top-level key per findings section (`error_anatomy`, `script_letters`,
`diacritics`, `difficulty`, `model_landscape`, `operational`, `corpus_health`),
each a JSON object of plain arrays/objects. A `meta` block records the seed,
`bench` version, run ids covered, model list, dataset list, per-section row
caps, and generation timestamp. Every model-keyed structure also carries an
`n_scored` / `n_attempted` pair so a chart can grey out thin cells.

## The `AlignmentRecord`

One record per `(model, dataset, sample_id)` **successful** prediction.
Errored / refused lines get a stub record (`failure_class` + identifiers only,
no ops).

### Construction

`jiwer.process_characters(ref, hyp)` yields `AlignmentChunk`s
(`equal` / `substitute` / `insert` / `delete` with ref/hyp index spans). Chunks
expand into per-character ops:

- `substitute` chunk, equal span length → one `(ref_char, hyp_char)` sub pair
  per position.
- `substitute` chunk, unequal span → align the shorter side positionally, spill
  the remainder into `insert` / `delete`. (Documented convention; matches how
  CER already counts these characters.)
- `insert` / `delete` → per-character `hyp_char` / `ref_char` op.

### Fields

| field | profile | notes |
| --- | --- | --- |
| `model`, `dataset`, `sample_id` | — | identity |
| `failure_class` | — | `ok` / `empty` / `refusal` / `meta_commentary` / `wrong_script` / `prompt_echo` / `rate_limited` / `other_error` (from `refusal.py`) |
| `char_ops` | `light` | `list[{op, ref, hyp, ref_i}]` — spine for confusion matrix, per-letter rates, S/I/D, rewrites |
| `word_ops` | `light` | from `jiwer.process_words` — word S/I/D, boundary analysis |
| `rasm_ops` | `light` + dot-strip | GT & pred mapped through the rasm table; `cer_light − cer_rasm` = pure dotting (i'jam) error |
| `diac_seq_ref` / `diac_seq_hyp` | `raw` | ordered harakat lists (`_harakat_only`); a second `process_characters` on the two sequences gives per-mark missed/inserted/substituted |
| `spacing_del`, `spacing_ins` | `light` | count of space-only del/ins ops — segmentation share of WER |
| `len_ref_chars`, `len_hyp_chars`, `len_ref_words`, `len_hyp_words` | `light` | length-bias scatter, CER-vs-length |
| `digit_swaps` | `light` | ref char is a digit, hyp char is a digit of a different script; keep direction |
| `presentation_form_chars`, `latin_run_len`, `has_code_fence` | raw `pred` | feeds `refusal.py` + presentation-form leakage |
| `cer_light`, `cer_raw`, `cer_rasm`, `wer_light` | — | cheap to carry; several reducers need them without re-scoring |

### Rasm table & letter groups

Hand-defined data in `align.py`, cross-checked against `pyarabic`:

- **Rasm map**: dot-bearing letters → undotted skeleton
  (ب/ت/ث/ن/ي → ٮ, ج/خ → ح, ذ → د, ز → ر, ش → س, ض → ص, ظ → ط, غ → ع,
  ف/ق → ٯ, ة → ه, …). Applied after `light` normalization and harakat strip.
- **Group tags** attached to every letter for roll-ups: `dot_confusable`,
  `hamza_carrier`, `alef_form`, `taa_haa`, `yaa_alefmaqsura`, `sun_letter`,
  `moon_letter`.

The record is an internal dataclass; it is **not** serialised into
`findings.json` wholesale — only reductions are. `--dump-records` is the escape
hatch.

## Leaderboard "Findings" tab — mechanics

- **Tab bar** above the header: `Leaderboard` · `Findings & analysis`. Two
  sibling `<div class="view">` containers; a ~15-line vanilla-JS toggle swaps
  `hidden` and swaps the sidenav `<ol>` to that view's sections. Choice
  persisted in `localStorage`; reflected in the URL hash
  (`#findings/script-letters`) for deep links. No framework; matches
  `_TOC_JS` style.
- `render()` splits into `render_leaderboard_view(rows)` (today's sections,
  untouched) and `render_findings_view(findings)` (the 7 sections). Existing
  `_panel()` / `_toc()` helpers reused.
- New module `scripts/_leaderboard_findings.py` holds the 7 `_render_*`
  functions, the chart primitives, and the CSS block — keeps
  `make_leaderboard.py` from ballooning. Imported by it.
- **Size budget:** `findings.json` embeds as one
  `<script type="application/json">` blob; charts build client-side. Confusion
  drill-down crops are **not** embedded — they reuse the already-embedded
  review-image pool, falling back to "no image". `bench analyze` caps per-section
  row counts (top-N letters, top-N rewrites, worst-N samples) like the review
  browser's `WORST_PER_MODEL`. Default caps: 40 confusion pairs, 30 troublesome
  letters, 25 rewrite patterns, 30 samples per difficulty list, 12 length bins.
  Target: findings view adds < 400 KB.
- **Artifact publish:** unchanged — `make_leaderboard.py` writes
  `results/leaderboard.html`, the notebook cell publishes it. `U+FFFD` scrub
  still applies to the whole fragment.

## Stats methods (pure numpy, seeded)

- **Bootstrap CI** — per `(model, dataset)`: resample sample-level
  `(err_chars, ref_chars)` pairs with replacement, `B = 2000`, recompute
  micro-CER, report 2.5 / 97.5 percentiles. Global seed `1234` in `findings.py`
  → reproducible `findings.json`. Rank CIs: one joint resample across all
  models, rank per replicate, report rank min / max / mode.
- **Win-rate / Bradley–Terry** — on lines both models scored, A beats B if
  lower CER-light (tie → 0.5). BT strengths via iterative MM update (~50 iters;
  fine for ~15 models), anchored so `mean(log strength) = 0`.
- **Refusal ruleset** (`refusal.py`, ordered, first match wins):
  1. `rate_limited` — stored error matches `429|rate.?limit`
  2. `other_error` — any other non-empty error string
  3. `empty` — cleaned prediction < 2 chars
  4. `wrong_script` — cleaned prediction ≥ 8 chars and Latin-char ratio > 0.5
     of non-space chars (the length guard keeps a short Arabic line with one
     borrowed Latin token from tripping it)
  5. `meta_commentary` — matches any of
     `i (cannot|can'?t|am unable)`, `as an ai`, `لا (أستطيع|يمكنني)`,
     `the (text|image) (says|reads|shows)`, `here is the`, or contains a
     ``` fence
  6. `prompt_echo` — ≥ 0.8 token overlap with the known prompt template
  7. else `ok`

  Phrase list is a module constant, easy to tune.
- **Suspected-bad-GT score** — for lines scored by ≥ 3 models:
  `mean_pairwise_pred_CER` (models vs. each other) low **and**
  `mean_pred_vs_GT_CER` high → rank by
  `(1 − mean_pairwise_pred_CER) × mean_pred_vs_GT_CER`.
